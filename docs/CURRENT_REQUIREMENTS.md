# 抖音直播录制与 B站/网盘投稿系统需求

## 1. 产品目标

- 做成其他人也能直接安装使用的软件，而不是只服务本机的一次性脚本。
- 支持多个主播同时监控、同时录制、同时上传，互不阻塞。
- 录制结束后自动处理并上传 B站，可选备份到网盘，按规则自动释放本地空间。
- 所有故障恢复必须是通用流程，不能依赖一次性人工修补或临时脚本。

## 2. 主播管理

- 可以添加多个主播。
- 支持抖音主页链接、直播间链接、分享短链解析。
- 必须从分享文本中解析出可长期监控的直播间地址，而不是只保存主页或分享短链。
- 每个主播保存独立配置。
- 支持删除主播，删除后相关线程、监控和待执行任务必须停止。
- 支持每个主播单独开始、暂停、恢复。
- 支持只记录直播数据、不录制视频的监控模式。

## 3. 每个主播可单独设置

- 主播名称。
- 直播间地址。
- 是否投稿公开。
- 是否录制弹幕。
- 是否上传网盘。
- 网盘类型、remote 路径。
- B站合集。
- 固定排班、全天轮询或手动开启。
- 一场或多场直播时间。
- 标题模板、标签、分区、来源等投稿参数。
- 录像模式：实际录制，或只记录直播数据。

## 4. 全局设置

- 默认缓存空间为 10 GB，用户可手动修改。
- 显示“当前已占用 / 总分配空间”。
- 录制清晰度、帧率。
- 根据清晰度显示一小时预估占用。
- 投稿后是否删除本地。
- 上传重试次数，自动重试最多 2 次。
- 轮询间隔、断流重连时间。
- 迟到判定阈值，默认 5 分钟。
- 最短可上传时长和最小文件大小，过短片段不上传并自动清理。

## 5. 直播检测与排班

- 支持固定时间排班。
- 支持全天轮询，并明确轮询频率。
- 支持手动检测。
- 排班必须能正确保存，不能保存后跳回全天轮询。
- 开始检测时间应早于主播设定开播时间，不能等到开播后很久才发现。
- 一次直播中断后重新开播，只要在重连宽限期内，应继续同一场录制，不重新计为迟到。
- 到达主播设置的结束时间后，如果主播仍在直播，应继续录制，不能直接停止。

## 6. 录制与分段

- 一场直播从开始到结束视为一个直播场次。
- 每 1 小时切一个 P。
- 同一场直播的 P1、P2、P3 必须属于同一个 B站稿件，共用一个 BVID。
- P1 创建投稿，P2 及之后使用 append 追加为分 P。
- 每个 P 完成后立即进入上传流程，不等待整场直播结束。
- 录制、渲染、上传、网盘备份和下一段录制应并行或排队执行。
- 多主播之间必须并行，任何主播的上传失败不能阻塞其他主播。
- 爆弹幕需要烧录进视频。
- 爆弹幕效果为从右向左滚动，分轨道错开，速度可读。
- 字幕、中文和 emoji 不能乱码。
- 断流、崩溃、重启后应恢复已完成的片段和未完成的上传。

## 7. 本地文件与目录

- 本地视频目录结构：
  - 根目录
  - 主播名
  - 日期
  - 场次目录
  - 当场的 P01、P02、P03 文件
- 每个主播显示独立占用空间。
- 每个主播都能打开对应视频文件夹。
- 暂停、退出、崩溃、重启不能丢失已录制内容。
- 支持暂停时询问：上传当前内容、仅保留本地、停止并删除。
- 应用退出时必须结束所有子进程。
- 重新打开应用后应继续补传未完成任务。

## 8. B站上传

- 场次标题必须包含主播名、实际检测到的开播时间和房间标题。
- 支持公开或仅自己可见。
- 支持同场多 P 追加到一个 BVID。
- 上传失败后保留本地文件并可重试。
- 自动重试最多 2 次，避免触发 B站投稿频繁限制。
- 相同标题上传失败后，重试时可以更换标题。
- 支持每个 P 单独暂停、重试、停止。
- 上传列表和稿件状态分开展示。
- 能看到正在审核、转码、开放浏览等稿件状态。
- 上传过程显示进度、速度、ETA、BVID。
- 上传失败不能影响其他主播和其他 P。
- 不区分名字冲突导致无法投稿时，应支持自动换名重试。

## 9. 网盘备份

- 是否网盘备份由每个主播单独决定，不默认全部开启。
- 添加主播时，应为该主播在网盘根目录下创建独立主播文件夹。
- 网盘路径示例：
  - 主播目录
  - 日期目录
  - 直接存放烧录后的 MP4
- 分 P 不单独建文件夹。
- 只上传烧录后的最终视频，不上传 XML、FLV 或临时文件。
- 网盘上传与 B站上传相互独立、并行执行。
- 网盘失败不能阻塞 B站和其他主播。
- 网盘失败后必须支持补传，不补传 B站。
- 能单独看到网盘上传进度和状态。
- 支持夸克、百度等网盘接入。
- 当前重点问题：OpenList/夸克 API 单连接上传速度慢，需要调研更好的夸克上传方案。
- 候选方向：
  - 夸克私有 API 分片并发上传。
  - 使用支持多分片并发的夸克 SDK/CLI。
  - 官方客户端 VIP 加速通道与自动化的配合方式。
  - 其他可并行分片且稳定性更好的网盘后端。

## 10. 本地删除规则

- 如果主播关闭网盘备份：B站上传确认后可以删除本地。
- 如果主播开启网盘备份：必须 B站和网盘都上传成功后，才允许删除本地。
- 正在录制、待上传、上传中、网盘未完成、重试等待的文件不能删除。
- 删除后不能残留 P 文件、FLV、XML、弹幕运行目录或缓存。
- 删除动作必须自动执行，不能依赖用户手工清理。

## 11. 主界面与交互

- 界面应像正式桌面应用，而不是不断刷新的网页。
- 固定窗口高度，各区域内部滚动，避免页面无限变长。
- 不要闪烁刷新，刷新时不能打断输入和操作。
- 使用白色和浅色为主，避免黑绿风格。
- 按功能拆分为独立侧栏：
  - 总览
  - 主播监控
  - 录制状态
  - B站上传队列
  - B站稿件状态
  - 网盘上传
  - 视频库
  - 日志
  - 数据统计和报告
- 主播卡片显示：
  - 是否正在检测、开播、录制、上传、等待空间、异常
  - 当前占用空间
  - 录制和上传两个状态必须分开显示
- 上传列表提供暂停、重试、停止、删除按钮。
- 全局暂停提供继续录制、暂停并上传、停止并删除。
- 每个主播提供单独开始和暂停按钮。
- 清除缓存不能删除正在录制或待上传内容。
- 控制台不能留过多空白。
- 稿件状态不能被固定区域遮挡。

## 12. 数据统计与报告

- 每个主播按月记录：
  - 开播天数
  - 直播场次
  - 总直播时长
  - 迟到次数
  - 迟到分钟数
  - 按时率
- 一天多场直播必须分别记录。
- 迟到按设定的开播时间计算，默认阈值 5 分钟。
- 断流后重新开播不重复计迟到、不重复计场次。
- 主播详情页展示图表。
- 支持周报和月报。
- 报告应图文并茂，并支持导出 PDF。
- 月未结束时不能自动误生成完整月报。
- 每个主播都有独立报告生成入口。

## 13. 稳定性与恢复

- 单一应用实例，不能同时运行多个控制台和多个 worker。
- worker 使用进程锁，只有一个录制进程。
- 启动时清理旧版本遗留进程。
- 崩溃或强退后，重新启动能恢复：
  - 已完成的 P
  - 未完成的上传
  - 中断的 `.part`
  - 未完成的网盘备份
- 用户退出应用时所有进程结束。
- 下载、渲染、上传、网盘上传互不误杀。
- 失败任务自动退避重试，不能无限快速重试。
- 任何一次异常都要通过通用修复流程处理，不能只修当前这一条数据。

## 14. 当前待解决项

- 夸克网盘通过 OpenList 上传速度约为 14.5 Mbps，明显低于 B站上传。
- 需要确认夸克官方 VIP 是否只加速官方客户端，不加速第三方 API。
- 需要调研并验证支持夸克分片并发的上传实现。
- 目标是在保持 B站和网盘都成功后才删除本地的规则不变的前提下，提高网盘上传速度和稳定性。
