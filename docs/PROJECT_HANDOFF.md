## 3. 做好的成品是什么

这是一个 macOS 桌面应用加后台录制服务，主要能力如下：

- 多主播同时监控和录制。
- 支持抖音主页、直播间和分享短链解析。
- 支持固定排班、全天轮询、手动检测。
- 每 1 小时切一个 P。
- 同一场直播的 P1、P2、P3 共用一个 B站 BVID，后续 P 使用 append 追加。
- 录制和上传并行执行，不等待整场直播结束。
- 多主播、多 P 上传互不阻塞。
- 支持公开或仅自己可见投稿。
- 支持每个主播单独设置合集、弹幕、网盘和排班。
- 支持弹幕烧录，弹幕从右向左滚动并分轨错开。
- 支持 B站上传队列、进度、速度、ETA、BVID 和稿件状态。
- 支持夸克/百度等网盘备份。
- 支持 B站上传和网盘备份分别暂停、重试、停止和补传。
- 支持应用退出后结束进程，重新打开后恢复未完成上传。
- 支持主播排班和固定开播时间，避免全天过度轮询。
- 支持主播直播数据统计、图表、周报和月报导出。
- 本地目录按主播、日期、场次和 P 分目录保存。

## 4. 当前删除规则

- 如果主播没有开启网盘备份：
  - B站上传成功后可以删除本地。
- 如果主播开启了网盘备份：
  - B站和网盘都上传成功后，才删除本地。
- 正在录制、待上传、上传中、网盘未完成和等待重试的文件不能删除。
- 删除后不能残留 MP4、FLV、XML、弹幕工作目录和缓存。

## 5. 怎么做的

### 5.1 技术栈

- Python 3.14
- FastAPI：本地控制台和 API
- pywebview：macOS 桌面窗口
- PyInstaller：打包后台运行程序
- 原生 Objective-C 启动器：生成标准 macOS `.app`
- biliup / stream-gears：抖音直播流和弹幕下载
- FFmpeg：弹幕字幕渲染、视频重新封装
- Biliup CLI：B站投稿和分 P append
- OpenList：夸克、百度等网盘统一接入
- rclone：与 OpenList WebDAV/API 交互
- ThreadPoolExecutor：并行上传任务
- `flock` 文件锁：单实例和单 P 上传互斥
- JSON / TOML：会话、配置、上传状态和统计持久化

### 5.2 主要模块

- `src/douyin_bili_recorder/pipeline.py`
  - 录制、分段、恢复、上传、网盘、清理和统计主流程。
- `src/douyin_bili_recorder/uploader.py`
  - B站投稿和 append 上传。
- `src/douyin_bili_recorder/cloud_uploader.py`
  - 网盘上传。
- `src/douyin_bili_recorder/openlist_api.py`
  - OpenList 原生上传接口。
- `src/douyin_bili_recorder/service_control.py`
  - 服务启停、状态、进程管理和上传控制。
- `src/douyin_bili_recorder/runtime_cleanup.py`
  - 旧进程清理和应用单实例保护。
- `src/douyin_bili_recorder/webapp.py`
  - 本地控制台 API。
- `src/douyin_bili_recorder/web/`
  - 前端界面、样式和交互。

### 5.3 核心设计

- 一场直播一个 `session.json`。
- 每个小时一个 `SessionPart`。
- P1 创建 B站稿件，后续 P 通过 append 使用同一个 BVID。
- 上传队列、网盘队列和录制线程分离。
- 每个 P 使用独立文件锁，避免重复上传。
- 启动时扫描未完成会话、中断的 `.part`、孤儿 MP4，并自动恢复。
- 应用级控制锁和 worker 锁防止多开和重复录制。
- 应用关闭时只终止当前应用进程，不破坏已完成状态。
- 重新打开后自动恢复待上传和待备份任务。
- 清理逻辑按 B站状态和网盘状态共同判断，不能只依赖单一状态字段。
- 本地文件结构固定为：
  - `视频根目录 / 主播名 / 日期 / 场次目录 / P01、P02...`

# 二、要做的

这里包含需求文档中尚未完全落地、或者需要加固的部分。

## 1. 主播管理

- 支持添加多个主播。
- 支持抖音主页链接、直播间链接、分享短链解析。
- 必须从分享文本中解析出可长期监控的直播间地址，而不是只保存主页或短链。
- 每个主播保存独立配置。
- 支持删除主播，删除后相关线程、监控和待执行任务必须停止。
- 支持每个主播单独开始、暂停、恢复。
- 支持只记录直播数据、不录制视频的监控模式。

## 2. 每个主播可单独设置

- 主播名称。
- 直播间地址。
- 是否投稿公开。
- 是否录制弹幕。
- 是否上传网盘。
- 网盘类型、remote 路径。
- B站合集。
- 固定排班、全天轮询或手动开启。
- 一场或多场直播时间。
- 标题模板、标签、分区、来源等投稿参数。
- 录像模式：实际录制，或只记录直播数据。

## 3. 全局设置

- 默认缓存空间 10 GB，用户可手动修改。
- 显示“当前已占用 / 总分配空间”。
- 录制清晰度、帧率。
- 根据清晰度显示一小时预估占用。
- 投稿后是否删除本地。
- 上传重试次数，自动重试最多 2 次。
- 轮询间隔、断流重连时间。
- 迟到判定阈值，默认 5 分钟。
- 最短可上传时长和最小文件大小，过短片段不上传并自动清理。

## 4. 直播检测与排班

- 支持固定时间排班。
- 支持全天轮询，并明确轮询频率。
- 支持手动检测。
- 排班必须能正确保存，不能保存后跳回全天轮询。
- 开始检测时间应早于主播设定开播时间。
- 一次直播中断后重新开播，只要在重连宽限期内，应继续同一场录制，不重新计迟到。
- 到达主播设置的结束时间后，如果主播仍在直播，应继续录制，不能直接停止。

## 5. 录制与分段

- 一场直播从开始到结束视为一个直播场次。
- 每 1 小时切一个 P。
- 同一场直播的 P1、P2、P3 必须属于同一个 B站稿件，共用一个 BVID。
- P1 创建投稿，P2 及之后使用 append 追加为分 P。
- 每个 P 完成后立即进入上传流程，不等待整场直播结束。
- 录制、渲染、上传、网盘备份和下一段录制应并行或排队执行。
- 多主播之间必须并行，任何主播的上传失败不能阻塞其他主播。
- 爆弹幕需要烧录进视频。
- 爆弹幕效果为从右向左滚动，分轨道错开，速度可读。
- 字幕、中文和 emoji 不能乱码。
- 断流、崩溃、重启后应恢复已完成的片段和未完成的上传。

## 6. 本地文件与目录

- 本地视频目录结构：
  - 根目录
  - 主播名
  - 日期
  - 场次目录
  - 当场的 P01、P02、P03 文件
- 每个主播显示独立占用空间。
- 每个主播都能打开对应视频文件夹。
- 暂停、退出、崩溃、重启不能丢失已录制内容。
- 支持暂停时询问：上传当前内容、仅保留本地、停止并删除。
- 应用退出时必须结束所有子进程。
- 重新打开应用后应继续补传未完成任务。

## 7. B站上传

- 场次标题必须包含主播名、实际检测到的开播时间和房间标题。
- 支持公开或仅自己可见。
- 支持同场多 P 追加到一个 BVID。
- 上传失败后保留本地文件并可重试。
- 自动重试最多 2 次，避免触发 B站投稿频繁限制。
- 相同标题上传失败后，重试时可以更换标题。
- 支持每个 P 单独暂停、重试、停止。
- 上传列表和稿件状态分开展示。
- 能看到正在审核、转码、开放浏览等稿件状态。
- 上传过程显示进度、速度、ETA、BVID。
- 上传失败不能影响其他主播和其他 P。
- 不区分名字冲突导致无法投稿时，应支持自动换名重试。

## 8. 网盘备份

- 是否网盘备份由每个主播单独决定，不默认全部开启。
- 添加主播时，应为该主播在网盘根目录下创建独立主播文件夹。
- 网盘路径示例：
  - 主播目录
  - 日期目录
  - 直接存放烧录后的 MP4
- 分 P 不单独建文件夹。
- 只上传烧录后的最终视频，不上传 XML、FLV 或临时文件。
- 网盘上传与 B站上传相互独立、并行执行。
- 网盘失败不能阻塞 B站和其他主播。
- 网盘失败后必须支持补传，不补传 B站。
- 能单独看到网盘上传进度和状态。
- 支持夸克、百度等网盘接入。
- 当前重点问题：OpenList / 夸克 API 单连接上传速度慢。

## 9. 本地删除规则

- 如果主播关闭网盘备份：B站上传确认后可以删除本地。
- 如果主播开启网盘备份：必须 B站和网盘都上传成功后，才允许删除本地。
- 正在录制、待上传、上传中、网盘未完成、重试等待的文件不能删除。
- 删除后不能残留 P 文件、FLV、XML、弹幕运行目录或缓存。
- 删除动作必须自动执行，不能依赖用户手工清理。

## 10. 主界面与交互

- 界面应像正式桌面应用，而不是不断刷新的网页。
- 固定窗口高度，各区域内部滚动，避免页面无限变长。
- 不要闪烁刷新，刷新时不能打断输入和操作。
- 使用白色和浅色为主，避免黑绿风格。
- 按功能拆分为独立侧栏：
  - 总览
  - 主播监控
  - 录制状态
  - B站上传队列
  - B站稿件状态
  - 网盘上传
  - 视频库
  - 日志
  - 数据统计和报告
- 主播卡片显示：
  - 是否正在检测、开播、录制、上传、等待空间、异常
  - 当前占用空间
  - 录制和上传两个状态必须分开显示
- 上传列表提供暂停、重试、停止、删除按钮。
- 全局暂停提供继续录制、暂停并上传、停止并删除。
- 每个主播提供单独开始和暂停按钮。
- 清除缓存不能删除正在录制或待上传内容。
- 控制台不能留过多空白。
- 稿件状态不能被固定区域遮挡。

## 11. 数据统计与报告

- 每个主播按月记录：
  - 开播天数
  - 直播场次
  - 总直播时长
  - 迟到次数
  - 迟到分钟数
  - 按时率
- 一天多场直播必须分别记录。
- 迟到按设定的开播时间计算，默认阈值 5 分钟。
- 断流后重新开播不重复计迟到、不重复计场次。
- 主播详情页展示图表。
- 支持周报和月报。
- 报告应图文并茂，并支持导出 PDF。
- 月未结束时不能自动误生成完整月报。
- 每个主播都有独立报告生成入口。

## 12. 稳定性与恢复

- 单一应用实例，不能同时运行多个控制台和多个 worker。
- worker 使用进程锁，只有一个录制进程。
- 启动时清理旧版本遗留进程。
- 崩溃或强退后，重新启动能恢复：
  - 已完成的 P
  - 未完成的上传
  - 中断的 `.part`
  - 未完成的网盘备份
- 用户退出应用时所有进程结束。
- 下载、渲染、上传、网盘上传互不误杀。
- 失败任务自动退避重试，不能无限快速重试。
- 任何一次异常都要通过通用修复流程处理，不能只修当前这一条数据。

## 13. 架构加固建议

- `session.json` 迁到 SQLite，作为唯一真相源。
- SQLite 存 `anchors / sessions / parts / upload_jobs / stats`。
- `session.json` 只作为导出或调试快照。
- 所有状态变更走事务。
- 文件锁只锁“上传动作”，不锁数据库。
- B站 append 必须幂等。
- 退出时回收 FFmpeg、biliup、rclone、OpenList 等子进程。
- 全局带宽调度：B站优先，网盘限速或低优先级。
- 每个分 P 统一状态机：
  - 待录制 → 录制中 → 待渲染 → 渲染中 → 待上传B站 → B站上传中 → 待网盘 → 网盘上传中 → 可删除 → 已删除
  - 异常分支：重试等待 / 暂停 / 失败 / 空间不足 / 断流恢复

# 三、等待验证的方案

## 1. 夸克分片并发上传

当前问题：OpenList `/api/fs/put` 单连接，实测约 14.5 Mbps。  
目标：验证夸克第三方 API 是否能稳定分片并发，找到速度拐点。

候选项目：

- **QuarkPan（Python 客户端）**
  - 大文件自动分片。
  - 文件 ≥5MB 时分割为 4MB 分片并行处理。
  - 支持断点续传。
  - 与当前 Python 技术栈匹配度最高。

- **libquarkpan（Rust 客户端库）**
  - 异步 Rust 客户端。
  - 提供分片上传、分片级重试。
  - 可导出 `UploadResume` 状态用于断点续传。
  - 适合关键上传模块引入 Rust 组件。

- **kuake-pipe（Python CLI）**
  - 不依赖夸克 PC 客户端。
  - 通过 Cookie 鉴权直接调用夸克云盘 HTTP API。
  - v0.4 改用直接 PUT，对 headless / CI 友好。

- **quark-backup（官方 CLI 封装）**
  - 调用夸克官方 `quarkclouddrive` CLI。
  - 如果官方 CLI 未来优化上传通道，可间接受益。
  - 需验证官方 CLI 是否支持并发分片。

验证矩阵：

- 分片大小：4MB / 8MB / 16MB。
- 并发数：2 / 4 / 8。
- 文件大小：1GB / 5GB / 20GB。
- 时段：白天 / 晚高峰。
- 观察：是否触发风控、限速、封禁。
- 目标：找到稳定拐点，而不是并发越大越好。

## 2. 替代网盘后端

如果夸克第三方 API 限制无法突破，评估其他网盘。

- **百度网盘：bypy-next**
  - `bypy` 的活跃分叉。
  - 新增 `--upload-threads N`，默认 4 线程。
  - 用于单文件分片并发上传。
  - 实测 100MB 文件从 22 秒降至 6 秒，提速约 3.7 倍。
  - 可作为主要备份后端候选。

- **阿里云盘：aliyunpan**
  - 功能丰富的命令行客户端。
  - 上传管理器提供分片上传、文件校验和并发控制。
  - 大文件自动分割为小块并行上传。
  - 有资料提到可能不支持单文件并发上传，需实测。

- **115 网盘：fake115uploader / 115driver**
  - `fake115uploader` 模拟 115 客户端上传。
  - 支持通过参数指定分片数量，1 到 10000。
  - `115driver` 提供带阿里云 OSS 分片上传的 CLI 工具。
  - 可作为备选。

- **OneDrive：OneDriveUploader**
  - Go 编写。
  - 支持自定义上传分块大小和多线程上传。
  - 适合有国际网络环境时使用。

## 3. OpenList 增强分支

- **OpenList_Chunk**
  - OpenList 的增强分支。
  - 专门支持大文件分片上传。
  - 用于绕过 CDN 上传大小限制。
  - 如果不想更换整个上传链路，可尝试替换当前 OpenList。

## 4. rclone 优化配置

如果继续用 rclone 通过 WebDAV 挂载夸克：

- `--multi-thread-streams`：单文件多线程上传。
- `--multi-thread-chunk-size`：分块大小。
- 需确认夸克 WebDAV 后端是否真正支持单文件分片。
- 如果不支持，这些参数可能只对多文件并发有效。

## 5. 官方 VIP 通道验证

- 确认夸克 VIP 是否只加速官方客户端，不加速第三方 API。
- 抓包官方客户端上传流程，确认：
  - 预上传；
  - 分片上传；
  - 并发分片；
  - 合并；
  - 是否走不同域名 / 协议。
- 如果官方客户端多连接，而第三方 API 单连接，基本确认 VIP 只加速官方通道。

## 6. 最终判断标准

- 优先集成 **QuarkPan**，验证夸克分片并发是否可行。
- 如果 QuarkPan 改善明显，封装成 `QuarkDriver`。
- 如果改善有限，说明问题在夸克第三方 API 整体限速策略。
- 此时应认真评估将 **百度网盘 bypy-next** 作为主要备份后端。
- 保持“B站 + 网盘都成功才删除本地”的规则不变。
- 夸克可降级为“可选低速备份”，或只对重要场次开启。

1. **SQLite + 状态机 + B站 append 幂等**：解决恢复和重复上传。
